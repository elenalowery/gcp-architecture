ML Patterns on GCP

Google Cloud Platform

GCP provides an integrated ML platform spanning data exploration, model development, training, evaluation, and inference. Agent Studio (Colab Enterprise notebooks) sits at the centre of the interactive development workflow, connecting directly to BigQuery, Cloud Storage, and managed training infrastructure.

Key GCP ML Services
Agent Studio (Colab Enterprise) AutoML Custom Training (GPUs / TPUs) Model Registry Model Monitoring Pipelines BigQuery ML Feature Store Batch Prediction Online Prediction Endpoints

Data scientists use Agent Studio (Colab Enterprise notebooks) to explore data, engineer features, and train models. Data flows from BigQuery, Cloud Storage, and streaming sources. Trained models are registered and deployed from the same platform.

Fig 1 — Data Exploration & ML Model Building

Agent Studio Capabilities

  • Managed Jupyter notebooks — no infra to provision
  • Native BigQuery integration — query directly in cells
  • Access to GPU / TPU runtimes for training
  • Integrated with Experiments for run tracking
  • Shareable, version-controlled environments

Data Prep Best Practices

  • Use BigQuery for SQL-based feature engineering at scale
  • Store offline features in Feature Store for training/serving consistency
  • Export to GCS in Parquet before large training jobs
  • Version datasets alongside model versions

Model Development Workflow

  • Prototype in notebook → productionise with Pipelines
  • Use AutoML as a baseline before custom training
  • Track every experiment; compare metrics in Model Registry
  • Evaluate on held-out and sliced data before registration

ML inference runs in two modes. Batch prediction processes large datasets asynchronously and stores results in BigQuery for downstream consumption. Real-time prediction exposes a managed endpoint that client applications invoke synchronously with low latency.

Fig 2 — ML Inference: Batch & Real-Time

Batch Inference

  • Triggered by Cloud Scheduler or Pipelines step
  • Input: BigQuery table or GCS file export
  • Results written to BigQuery partitioned by run date
  • Consumed by BI dashboards, downstream pipelines, data exports
  • Cost-efficient — pay per prediction job, no idle endpoint

Real-Time Inference

  • Managed endpoint — automatic scaling to zero or min replicas
  • REST and gRPC supported; <100ms p99 for most tabular models
  • Online Feature Store lookup for consistent features at serving time
  • Traffic splitting for A/B tests and canary rollouts
  • Dedicated endpoints for throughput isolation

When to Use Each

  • Batch — nightly scoring, fraud risk reports, churn propensity, recommendations pre-compute
  • Real-time — fraud detection at transaction time, personalisation, content ranking, price optimisation
  • Hybrid — batch for population scoring + real-time for individual overrides

Architecture Considerations

Google Cloud Platform

Data & Feature Management

Training–serving skew is one of the most common causes of production model degradation. Feature Store eliminates it by sharing feature definitions between training and serving.

Feature Store — define features once; use in training (offline) and serving (online) consistently Dataset versioning — snapshot training data with timestamps; link dataset version to model version BigQuery as offline store — query features at point-in-time using FOR SYSTEM_TIME AS OF Dataflow for feature pipelines — compute and backfill features at scale; write to Feature Store Training–serving skew — validate that online feature values match training distribution before launch

Training Infrastructure

Match compute to model complexity. Use managed notebooks for exploration; move to reproducible Pipelines for production training runs.

Agent Studio notebooks — fast iteration; GPU runtimes; direct BigQuery access Pipelines — reproducible, version-controlled training DAGs; CI/CD for ML Custom Training — bring your own container; full framework control; A100 / TPU v4 available AutoML — strong baseline; no code required; good for tabular, image, text, video Distributed training — multi-node GPU via MirroredStrategy / Reduction Server for large models Spot / preemptible VMs — up to 80% cost reduction for fault-tolerant training jobs

Model Deployment & Serving

Choose serving strategy based on latency requirements, traffic volume, and cost tolerance.

Online Endpoint — REST/gRPC; autoscaling; traffic splits; <100ms; pay per request Batch Prediction — async; no idle cost; results in BigQuery; best for large-scale scoring Dedicated Endpoint — reserved capacity; no cold start; use for latency-critical production traffic Model versions & aliases — promote candidate → staging → prod without downtime; rollback in seconds Explainability — Shapley values and integrated gradients; required for regulated use cases Shadow mode — run new model in parallel to production; compare outputs without user impact

MLOps & Monitoring

Models degrade silently. Instrument every inference call; monitor data drift and prediction drift independently.

Model Monitoring — scheduled drift detection on prediction inputs vs. training baseline Experiments — track hyperparameters, metrics, and artefacts for every training run Pipelines CI/CD — trigger retraining on data drift alert or scheduled cadence Cloud Logging — log every prediction request + response for audit and debugging Cloud Monitoring — endpoint latency p50/p95/p99, error rate, request volume dashboards Data drift alerts — set thresholds on Jensen-Shannon divergence for feature distributions Lineage tracking — trace model back to dataset version, pipeline run, and training code commit

Security & Governance

ML workloads handle sensitive training data and model artefacts. Apply the same data security controls as production databases.

IAM roles — separate roles for data scientists, ML engineers, and pipeline service accounts VPC Service Controls — prevent training data exfiltration; restrict GCS and BigQuery to trusted perimeters CMEK — encrypt model artefacts and training data with customer-managed keys Private endpoints — deploy endpoints with no public IP; access via Private Service Connect PII in training data — apply Cloud DLP before ingestion; document data provenance for compliance Model cards — document model purpose, limitations, and evaluation results for governance
